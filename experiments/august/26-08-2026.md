# Dataset Alignment and Final Feature Construction

## 1. Overview

After completing the individual feature analysis for API, DLL, PE Header, and PE Section data, the next stage was to construct a single consistent malware dataset.

The objectives of this stage were:

- Align all four feature sources using SHA256.
- Identify samples common to all datasets.
- Verify target-label consistency.
- Select the final features from each feature group.
- Construct separate feature matrices.
- Merge all feature matrices into one unified dataset.
- Validate the resulting dataset.

---

## 2. Dataset Alignment

Four independent feature datasets were used:

- API
- DLL
- PE Header
- PE Section

SHA256 was selected as the common identifier because it uniquely identifies each malware sample.

The SHA256 values from all four datasets were compared to determine their intersection.

Only samples available across all four sources were retained for the final combined dataset.

---

## 3. Missing Sample Analysis

The number of samples absent from each individual source was examined during alignment.

Samples that were not available in all four sources were excluded from the final multimodal feature matrix.

This ensured that every final sample had a complete representation across:

- API features
- DLL features
- PE Header features
- PE Section features

---

## 4. Pairwise Dataset Overlap

Pairwise SHA256 intersections were calculated between every combination of the four datasets.

This was used to verify the degree of overlap between the individual feature sources before constructing the final intersection.

---

## 5. Target Consistency

The `Type` column was used as the classification target.

For all samples present in the common SHA256 intersection, the target values from the different datasets were compared.

This ensured that the same malware sample was assigned the same class regardless of the feature source.

Any inconsistencies would have indicated a possible data-integrity problem.
